# test_code/driver — 오프라인 검증

| 파일 | 내용 |
|---|---|
| `test_control.py` | FSM 전이·속도 법칙 19항목 |
| `test_odometry.py` | 시각 오도메트리 정확도 (알려진 전진량 복원) |

## 시각 오도메트리 — 알고리즘을 갈아엎었다

처음에 특징점 LK 광류로 만들었다가 버렸다. 두 가지가 원리적으로 안 맞았다.

**① 근접 벽면은 패치가 늘어난다.** LK 는 국소 평행이동을 가정하는데, 25mm 앞
관벽은 프레임 사이에 무늬가 **확대**된다. 실측으로 예측 변위 18.9px 중 3.3px,
**17% 만** 추적됐다.

**② 변위가 커질수록 수렴이 나빠진다.** 1mm 는 맞고 10mm 는 못 맞혔다. 운용
조건(10Hz, 0.1 m/s)에서 프레임당 전진이 정확히 10mm 라 그대로 쓸 수 없었다.

**자유도가 전진 하나뿐**이므로 2 자유도 광류 대신 Δz 를 직접 탐색하도록 바꿨다.
후보 Δz 마다 이전 프레임 화소를 예측 위치로 옮겨 상관을 재고 최적을 고른다.
스케일 변화가 모델 안에 들어 있어 두 문제가 모두 사라진다.

| 정답 | 측정 | 오차 |
|---|---|---|
| 1mm | 0.75mm | −0.25 |
| 5mm | 5.25mm | +0.25 |
| 20mm | 20.25mm | +0.25 |

오차 ±0.25mm 는 탐색 격자 분해능이다. 10Hz 기준 2.5 mm/s 로, 끼임 판정
임계(휠 속도의 30%)에 비해 충분히 작다.

## 합성 텍스처를 두 번 고쳤다

광류 성능이 아니라 **무늬의 성질을 재는 함정**을 두 번 밟았다.

- **단일 고주파** → 변위가 주기 절반을 넘는 순간 엉뚱한 주기에 달라붙음
- **저주파만** → 코너가 약해 추적 실패
- **프레임 간 동일한 센서 잡음** → 화면에 고정된 무늬가 되어 광류가 거기 고정,
  전진량이 0 으로 측정됨

지금은 옥타브 8개를 1/f 진폭으로 쌓은 광대역 무늬에 프레임마다 다른 잡음을
넣는다. 실제 강관 내벽(부식·스크래치)에 가깝다.
