# test_code — 오프라인 검증

**여기 있는 것은 전부 강제로 만든 시험용이다.** 실제 센서 입력도, 실제 물리
시뮬도 아니다. Isaac Sim 과 실기가 없는 상태에서 로직만이라도 검증하려고
입력을 계산으로 합성하거나 로봇 자세를 손으로 지정한 것들이다.

파일 최상단 배너로 구분한다.

| 배너 | 뜻 | 위치 |
|---|---|---|
| `[오프라인]` | 강제 입력·강제 자세. 이 디렉터리 | `test_code/` |
| `[실기]` | Isaac Sim 또는 실기에 붙어 도는 것 | `robot/`, `camera/`, `pipe/`, `condition/` |
| `[공용]` | 양쪽이 함께 쓰는 순수 로직 | `condition/detector.py` |
| `[자산생성]` | STL 등 자산을 만드는 빌드 도구 | `tools/` |

## robot/ — 2단 1관절 형상 검증

| 파일 | 하는 일 |
|---|---|
| `preview_assembly.py` | 직관·곡관 안 간섭 검사, 렌더 2장 |
| `animate_curve.py` | 곡관 통과 애니메이션 GIF |

산출물 — `preview_straight.png`, `preview_bent.png`, `curve_pass.gif`

### 무엇이 강제인가

**로봇이 스스로 굴러간 것이 아니다.** 배관 중심선을 따라 "이 위치에 놔라"라고
자세를 지정하고, 그때 관절이 얼마나 꺾이고 다리가 얼마나 눌리는지를 역기하로
푼 것이다. 접촉력·마찰·구동토크는 전혀 들어 있지 않다.

즉 **"들어갈 자리가 있는가"** 까지만 답한다.
**"제 힘으로 지나가는가"** 는 `pipe/curve_demo.py`(Isaac Sim 필요)의 몫이다.

### 결과

| 항목 | 값 | 한계 | 판정 |
|---|---|---|---|
| 필요 관절각 | 35.79° | ±55° | 여유 19.21° |
| 본체·암 관벽 여유 | 8.01mm | — | 통과 |
| 필요 서스펜션 스트로크 | ±4.59mm | ±6mm | 여유 1.41mm |
| 휠 접촉 반경 | 50.00mm | DN100 내반경 50mm | 정확히 접함 |

**설계 문서의 곡관 산출식을 독립 재현했다** — `sagitta/2`, SR=R100mm 기준으로
±16.93mm(일체형 150mm) / ±2.46mm(62mm) 가 문서값과 소수점까지 일치.

**단 실제 필요 스트로크는 문서의 ±2.46mm 가 아니라 ±4.59mm 다.** 문서는 62mm
세그먼트 길이만 썼지만, 실제 조립체는 암 스태거(±10mm)와 암이 피벗 뒤로 29mm
뻗은 배치 때문에 휠 접촉점이 62mm 보다 넓게 퍼진다. 여유가 3.5mm 가 아니라 1.4mm.

### 애니메이션의 완화항

로봇을 중심선에 정확히 앉히면 한쪽 바퀴만 과도하게 눌려 스트로크가 한계
(−6.00mm)에 걸린다. 실제로는 6개 스프링이 균형점을 찾아 로봇이 살짝 편심하므로
`relax()` 가 그 자유도(단면 내 횡방향 이동)를 흉내낸다. 이 완화를 넣으면
−4.19 ~ +4.65mm 로 떨어져 `preview_assembly.py` 의 최적화 결과와 일치한다.

**독립적인 두 방법이 같은 답을 냈다는 점이 이 수치의 근거다.**

### 주의

`preview_bent.png` 의 점선은 **직관** 기준선이라 곡관 자세에서는 의미 없다.

## condition/ — 관 상태 판정 검증

| 파일 | 하는 일 |
|---|---|
| `make_scenes.py` | 시험 장면 11종 합성 (RGB + Depth) |
| `test_detector.py` | 전수 대조 + 임계값 분리도 |
| `mock_publisher.py` | 저장 장면을 ROS 토픽으로 발행 |

산출물 — `scenes/` (`*_depth.npy`, `*_rgb.npy`, `*.png`, `scenes_meta.json`)

### 무엇이 강제인가

**카메라 영상이 아니라 계산으로 그린 그림이다.** 배관 안에서 카메라가 보는
장면을 광선 추적으로 만들었다. 전방 220mm 에 조인트가 있고 그 너머 관이
지정한 만큼 어긋난 구조로 모델링한다.

**카메라 모델은 어안이다** — 1280×720, HFOV 140°, 등거리(r = f·θ), f = 523.9px.
`camera/config/camera.yaml` 과 맞춰져 있다. 광선을 단위벡터로 쏘므로 교점까지
거리가 곧 `distance_to_camera` 와 같은 의미가 된다.

실제 강관 내벽의 반사 특성·조명 불균일·RealSense 최소 측정 거리 문제는
**하나도 반영되어 있지 않다.**

### 장면 11종

| 장면 | 정답 | 비고 |
|---|---|---|
| `normal`, `normal_noisy` | NORMAL | 깊이 잡음 유무 |
| `misalign_2mm/5mm/12mm` | MISALIGNMENT | 등급 경계 확인 |
| `misalign_5mm_noisy` | MISALIGNMENT | 잡음 내성 |
| `disconnected`, `disconnected_off` | DISCONNECTED | 너머 반사 없음 |
| `undetermined`, `_mild`, `_heavy` | UNDETERMINED | 개구부 불규칙 강도 3단계 |

### 결과

**11종 전수 통과. 오프셋 실측 오차 최대 0.14mm.** (어안 기준)

ROS 파이프라인도 실제로 확인했다 — `mock_publisher` → 토픽 →
`pipe_condition_node` → `/condition`. 11장면이 순서대로 올바르게 판정되어 발행됐다.
(이 노트북에 `rclpy`·`cv_bridge` 가 있어 가능했다.)

### 임계값 분리도

| 지표 | 정상군 | 이상군 | 임계 | 판정 |
|---|---|---|---|---|
| Depth 무효 비율 | 0.00% | 4.67% (단절) | 2.0% | 분리 (여유 2.3배) |
| 원형도 | 0.884~0.898 | 0.259~0.863 | 0.60 | 분리 (간극 0.0215) |
| 윤곽 거칠기 | 0.0029~0.0075 | 0.0334~0.3004 | 0.015 | 분리 (간극 0.0259) |

**핀홀에서 어안으로 바꾸자 임계값이 조용히 깨졌다.** 거칠기 임계 0.0070 이
정상군 최대(0.0075) 안쪽으로 들어가 `misalign_12mm` 이 UNDETERMINED 로 오판됐다.
0.015 로 다시 잡았다. 화각이 넓어지면서 분리도 자체는 좋아졌다(원형도도 이제
단독으로 갈린다). 카메라를 바꿀 때마다 이 표를 다시 뽑아야 한다는 증거다.

### 이 검증으로 찾은 사양 버그 2개

**① 오프셋이 1.5배 과대평가된다.** 픽셀→mm 환산에 화면 중앙 깊이를 쓰면
2mm→3.04, 5mm→7.60, 12mm→18.49 로 나온다. 중앙 깊이는 먼 관 안쪽까지의
거리이지 개구부가 놓인 조인트 평면까지의 거리가 아니기 때문. 개구부 테두리
바깥 띠의 깊이를 쓰도록 고쳐 오차 0.10mm.

**② 원형도만으로는 UNDETERMINED 를 못 가른다.** `4πA/P²` 는 둘레에 좌우돼
완만한 요철에 둔감하다. 핀홀 75° 시절 약하게 불규칙한 개구부가 0.896 으로
정상군(0.887~0.902) 한복판에 들어와 **임계값을 어떻게 잡아도 겹쳤다.** 윤곽
반경의 상대 표준편차를 추가해 해결했다. 어안 140° 로 넓히니 원형도도 갈리게
됐지만, 거칠기 쪽 간극이 더 크므로 주 판별자는 그대로 둔다.

**③ 노드의 내부 파라미터가 카메라와 따로 논다.** 어안 전환 후 `camera_info` 의
`f` 를 받아도 `f_fish` 가 갱신되지 않아 **오프셋이 1.25배 틀어졌다**
(2.0→2.48mm). 화면에는 정상값처럼 보이므로 눈으로 못 잡는다. `on_info` 에서
`f_fish` 도 갱신하도록 고쳤다.

## 실행

```bash
# 형상
cd test_code/robot
python3 preview_assembly.py          # robot/meshes 와 spec/ 을 읽는다
python3 animate_curve.py --frames 72

# 판정
cd test_code/condition
python3 make_scenes.py --png
python3 test_detector.py

# ROS 연동 시험 (터미널 2개)
python3 ../../condition/node.py
python3 mock_publisher.py --dwell 12
```

`preview_assembly.py` 는 `robot/meshes/` 와 `spec/parts_meta.json` 을,
`test_detector.py` 는 `condition/detector.py` 를 상대 경로로 참조한다.
디렉터리 구조를 바꾸면 두 파일의 경로 상수를 같이 고칠 것.

## 공통 한계

- **전부 기하·합성 기준이다.** 물리(접촉·마찰·구동)와 실제 센서 특성은 없다
- 여기서 통과했다고 실기에서 통과한다는 뜻이 아니다. **반대로 여기서 실패하면
  실기에서는 확실히 실패한다** — 그 용도의 관문이다
- 임계값은 전부 합성 데이터에서 뽑은 **잠정치**다
